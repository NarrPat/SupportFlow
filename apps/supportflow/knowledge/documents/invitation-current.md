# 邀请排障概览 {#invitation.overview}
邀请失败诊断必须先确认当前客户、订阅、邀请记录、域名策略、邀请权限与邀请服务状态。
资料只提供排障依据，不能替代实时工具事实；缺失事实应列为未知，不能猜测根因。
完成只读诊断不表示已扩容、已发出邀请或已修复服务；任何业务变更必须另走授权和审批。

# 容量阻断 {#invitation.capacity}
基础席位是订阅自身的基础额度；临时席位是有明确到期时间的额外额度，授予临时席位不改变基础席位。有效容量等于基础席位加尚未到期的临时席位；临时席位在到期时刻及之后不生效。
剩余席位为有效容量减已用席位且最低为零；已用席位达到或超过有效容量时，新增成员邀请受到容量不足阻断。
容量不足只能作为已确认阻断之一，不得掩盖同时存在的域名、权限、有效期、订阅或服务问题。

# 其他阻断 {#invitation.other_blockers}
只有订阅状态为 active 才属于有效订阅；其他状态不得当作 active，未知状态仍需保留未知标记。
邮箱域名必须满足客户的允许列表；子域名只有显式允许时才按点边界匹配，缺少策略应标为未知。
邀请权限为 false 是权限阻断；权限配置缺失不得被解释成允许。
邀请有效区间为 created_at <= now < expires_at；尚未创建是未生效阻断，到期等号及之后是过期阻断。
邀请状态 joined 表示已加入，revoked 表示邀请已撤销；撤销旧邀请不得直接当作重复邀请。
邀请服务为 degraded 或 outage 是服务阻断；缺少服务信息或未知状态不得假定服务正常。
诊断必须保留同时成立的阻断因素；不得自动重新邀请，也不得用扩容掩盖其他未解决阻断。
